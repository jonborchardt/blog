## 1. The mixing model, exactly as implemented

All of it lives in `lib/song.mjs`. The order matters: each layer builds its pattern from the axes (`lib/layers.mjs`), then `song()` applies the mix material in this order: `.orbit(n)` → `position` → `velocity` → `humanize` → `compressor` → `room`. Then the `duck` wiring runs over the finished parts. Unset = untouched (the golden fixtures did not move when this shipped).

### `room` (song or section key)

`room: { size, fade, damping, dimension, ir, irbegin }`, a section's `room` overrides the song's. Each key becomes one superdough control call on every hap of every part in the section:

| key | superdough control | bounds (`ROOM_KEYS`) | what it does |
|---|---|---|---|
| `size` | `roomsize` | 0.05..60 s | reverb decay time in seconds. With an `ir` it **truncates** the impulse file to that many seconds and never stretches it (superdough `adjustLength`: a size longer than the file just plays the whole file) |
| `fade` | `roomfade` | 0..10 s | a ramp on the reverb's own head, scaling the impulse's first samples up from zero. Softens the reverb's attack "the way a pre-delay would without actually delaying it" (code comment). Not a true pre-delay |
| `damping` | `roomlp` | 0..20000 Hz | for the synthetic tail: the lowpass the tail starts at (`lpFreqStart`); for an `ir` it is still passed but the generator is bypassed |
| `dimension` | `roomdim` | 0..20000 Hz | synthetic tail only: the lowpass the tail ends at (`lpFreqEnd`) |
| `ir` | `ir` | a sample name | a convolution impulse from a loaded pack; checked like any `s()` name (`scripts/check.mjs` treats `room.ir` as a sound, so an unknown impulse fails the check) |
| `irbegin` | `irbegin` | 0..1 | read the impulse from this fraction of the file in; superdough wraps past 1 to the file's start. Refused without `ir` |

Superdough side (`node_modules/superdough/reverb.mjs`): `createReverb(duration, fade, lp, dim, ir, irspeed, irbegin)` makes one `ConvolverNode` per orbit; with `ir` the buffer is `adjustLength(size, ir, speed, irbegin)`, without it `reverbGen.generateReverb` synthesizes a decaying-noise tail. `superdoughoutput.mjs getReverb` regenerates the buffer whenever any of those parameters changes hap to hap; this is why every part on one orbit must want the same reverb (see orbits below) and why arrival's history has a "whistle/pop" bug fixed by giving the textures one `.size(.9)`.

### What `space` means once a room is set

Each layer's `space` axis cell writes two things (`lib/layers.mjs`, `piece(lo, base, hi)` maps axis 0/.5/1 → lo/base/hi, linear):

| layer | send (`room` control) | size (`size` = alias of `roomsize`) | other |
|---|---|---|---|
| pad | 0 / .3 / .9 | .4 / .6 / .95 | |
| melody | 0 / .2 / .9 | none (send only) | `delay` = (space − .5)·.8 above .5 |
| bass | (space − .5)·.6 above .5 | none (send only) | |
| drums (and perc) | (space − .5)·.8 above .5 | .3 / .3 / .8 | |
| fx, sample, raw | 0 / .5 / .95 | .3 / .8 / .95 | |

`withRoom` runs last, and `roomsize` and `size` are the same control (`@strudel/core controls.mjs`: `registerControl('roomsize', 'size', 'sz', 'rsize')`), so under a `room` with `size` the part's own size is overwritten and **`space` becomes purely the send amount** (plus the melody's delay amount, which is why the piano stays at or below .5: above it, a delay line "reads as a pop behind each note", header comment). Sends are per hap, so parts on one shared bus keep their own wet amounts.

### The generated impulse-response pack (`samples/user/rooms/`, CC0, `deploy: true`)

Generated by `scripts/ir.mjs` (`npm run ir`), committed as wavs (the Pages build never runs the generator). Nothing recorded, nothing downloaded: each is a **shoebox image-source model**:

- `taps(box)`: every mirrored copy of the source across the room's wall pairs up to `order` bounces is one tap, delayed by (distance − direct distance)/343 m/s, attenuated by `absorb^bounces · direct/dist`, panned by its lateral angle (equal-power). Times are relative to the direct path (so a big room does not add its own flight time on top of the pre-delay). The direct sound (0 bounces) is excluded: a send must not carry it.
- `impulse()`: `predelay` seconds of **digital silence**, then the taps as single samples, then a seeded (mulberry32, so a regenerated pack is byte-identical) noise tail decaying to −60 dB over `decay` s under a one-pole lowpass sliding from `lp` down to `damp` Hz ("the tail darkens as it dies"). Normalized to peak 1 (the convolver normalizes anyway).

| file | pre-delay | decay | box (w×d×h m), absorb, order | taps | tail lp → damp | size |
|---|---|---|---|---|---|---|
| `room.wav` | 8 ms | 0.9 s | 5×4×2.8, .55, 4 | 128 | 9000 → 2500 Hz | 160 KB |
| `plate.wav` | 15 ms | 1.8 s | 1.2×0.9×0.4 ("no geometry": dense taps from a tiny hard box), .8, 6 | 376 | 12000 → 4000 Hz | 320 KB |
| `hall.wav` | 30 ms | 3.2 s | 22×30×14, .72, 4 | 128 | 7000 → 1200 Hz | 570 KB |

`test/ir.test.mjs` pins: the head is exactly silent for the pre-delay, the first reflection lands within 60 ms after it, the file is exactly `predelay + decay` long (so `size` truncation is honest), stereo with non-zero width, and every song's `room.size` fits the impulse it names.

**Pre-delay via silent head and `irbegin`.** Superdough has no pre-delay control, so the pre-delay is baked into the file as leading silence; `irbegin` skips it: `songs/rooms.strudel` section `tight` plays `hall` from `irbegin: .015` (1.5% of 3.23 s ≈ 48 ms, past the 30 ms head), "the same room with the pre-delay removed", for A/B against `hall`. `songs/rooms.strudel` (hidden) is the listening test: one sparse marimba/rim/kick phrase through `dry` (no room key: synthetic tail, no early reflections, no gap), `small`, `plate`, `hall`, `tight`.

The skill's guidance: `{ ir: 'room', size: .9 }` for kits, breaks, anything dry; `{ ir: 'plate', size: 1.8, damping: 7000 }` for bells, glass, piano pop; `{ ir: 'hall', size: 3.2, damping: 4500 }` for a score or anything slow and dark; `{ size, fade, damping }` without `ir` "is the fallback, not the default". Which promoted song uses which: arrival hall 3.2; arc plate 1.8 (damping 6500); machine room **cut to .5 s** ("early reflections and a door, no tail; the machine stays dry"); the others per their notes.

### Orbits and `orbitKey`

Superdough keeps reverb and delay **per orbit** (a bus); a `ConvolverNode` per orbit. `orbitKey(layer, attrs, room)` in `lib/song.mjs` decides who may share a bus; two parts share one iff their reverb would be identical:

```
if (attrs.duck !== undefined || base === 'raw') return null;      // private orbit
if (room?.size !== undefined) return 'room';                     // one bus for the whole section
const prefix = room !== undefined ? 'room:' : '';                // a room without size still splits by size
if (SEND_ONLY.has(base)) return prefix + 'default';              // bass, melody: their cells never set a size
const space = attrs.space ?? 0.5;
return typeof space === 'number' ? `${prefix}${base}:${space}` : null;  // same layer kind at the same space value
```

Orbits are numbered in order of first appearance in the section. A ducked part is alone because the duck dips the whole orbit's gain; a `space` signal changes size per hap so it cannot share.

**The 13-part fact, recounted today** (temp script over `song()`'s built sections):

- arrival `threshold` now (`room: { ir: 'hall', size: 3.2 }`): **1 orbit**, all 13 parts.
- Commit `4d95feb` message: before that commit it was one orbit per part, "arrival's threshold ran 13 [convolvers]"; after: "Threshold: 13 -> 5, contact 11 -> 5, plea 10 -> 5". So the sequence is 13 → 5 → 1.
- machine `chorus3`: 3 orbits both before and now (bass and pad are ducked, so private; drums + melody share orbit 1 under the room).

### `position` → pan shift, and how `width` moves around it

`withPosition`: `pan = clamp((v.pan ?? 0.5) + position/2, 0, 1)` on every hap, compiled from source so the dump prints the number inlined. `position` is −1..1; `0` (or unset) is a no-op. Because it adds to whatever pan the layer already wrote, everything the layer does with pan moves *with* it:

- drums: a static per-voice spread of ±`piece(0, .1, .5)(width)` around the kit's centre (bd centre, others offset), so a kit's spread moves as one block.
- pad: `width` < .8 is a sine pan sweep of half-width `piece(0, .1, .5)(width)` at one cycle per 8 bars; `width` ≥ .8 is `.pan(.5).jux(rev)` (a doubled, mirrored copy of every voice: the load problem, see voices).
- melody: sine sweep of half-width (width − .5), one cycle per 4 bars; fx, sample, perc: per 2 bars.
- `position` on a swept pad shifts the whole sweep's centre.

Caveat for the post (measured today): the `pan` column of the measure table reads the **rendered** stem, including the sample's own stereo image and the stereo reverb return. Arrival's piano reads 0.74 with no `position` at all (the sample is right-heavy) and 0.76 at `position: .1`; `pad4` (bowed vibraphone, `position: -.35`, events carry `pan ≈ .33`) still measures 0.49 because at `space: .98` most of its energy is the hall's stereo return. `position` is real in the events (verified: harp haps `pan .35..`, vibraphone `.31..`); what the ear gets is position plus the room.

### `duck` / `duckDepth` / `duckAttack`

Written per section after every part is built: a part with `duck: 'drums'` gets the drums' haps pointed at its orbit: `duckorbit: [..., targetOrbit]`, `duckdepth: [..., duckDepth]`, `duckattack: [..., duckAttack]` appended on every hap of the *source* part (arrays, in step, so two parts ducking the same source each get their own depth). Errors: a part cannot duck itself; the source must exist in the section. Defaults `duckDepth .5`, `duckAttack .1`; bounds depth 0..1, attack 0..2 s.

Superdough (`superdoughoutput.mjs Orbit.duck`): at each source hit at time `t`, the target orbit's output gain does `exponentialRampToValueAtTime(clamp(1 − sqrt(depth), .01, current), t + onset)` then `exponentialRampToValueAtTime(1, t + onset + attack)`. `duckonset` is never written by strudel-bench, so onset = 0: the dip is instantaneous at the hit; **`duckAttack` is the recovery time**, not the attack (superdough's name). Depth in dB: .15 → gain .61 (−4.3 dB); .3 → .45 (−6.9); .35 → .41 (−7.8); .4 → .37 (−8.7); .5 → .29 (−10.7); .6 → .23 (−12.9).

**The fallback** (`lib/layers.mjs` pad layer): with no `duck` and pad `drive` > .5, the pad multiplies its gain by a `square.fast(4)` between `1 − (drive − .5)·2·.6` and 1, "sampled once per chord hap (continuous signals collapse per hap), so it reads as a per-chord level dip rather than a 4-per-cycle pump. a real sidechain is `duck: 'drums'`; this dip remains the no-duck fallback."

Written conventions from the skill: `bass: { duck: 'drums', duckDepth: .35 }`, `pad: { duck: 'drums', duckDepth: .15, duckAttack: .2 }`. In promoted songs: arc `low` .35/.12 s and `bed` .15/.2 s; machine bass .3/.1 s and sub pad .4/.15 s. Arrival ducks nothing (a 64 BPM score with a timpani pulse, no kick to make room for).

### `velocity`

A mini-notation string of per-step multipliers over one bar (`'.85 1 .9 1 .8 1 .9 .95'`; `'<[...] [...]>'` for two bars), applied as superdough's `velocity`, which simply multiplies gain (`superdough.mjs:611 gain *= velocity`) under the layer's own gain and the grid's accents. A `~` rest is refused with a message (a rest in the velocity pattern would drop the notes under it: `p.velocity(pattern)` keeps only steps velocity has a value for). The hook convention is a "phrase-shaped line", the same string on arrival's theme and arc's hook.

### `humanize` (the three curves)

`{ timingMs 0..200, velocity 0..1, length 0..1, correlation: 'bar' | 'phrase' | bars 0.25..64 }` (`'phrase'` = 4). One seeded generator `src(amt, k)` compiled from source, evaluated at the hap's start time `t` in cycles (bars):

```
curve(t) = amt * ( 0.5 * sin(2π t / per + φ(k))                       // slow wave over `correlation` bars
                 + 0.3 * sin(2π (t mod 1) * beats + φ(k+1))            // a fixed lean per beat position inside the bar
                 + 0.2 * ((sin(t * 127.1 + φ(k+2)) * 43758.5453) mod 1) )  // residual: the classic GLSL hash, sign kept, so ±0.2
φ(k) = round3( ((imul(seed, 2654435761) + k * 40503) >>> 0) / 2^32 * 6.2832 )
```

- **timing** (k = 1): `d = curve(timingMs/2000 · cps)(t) + timingMs/2000 · cps` cycles, added to the hap's whole *and* part span. Since the sum is in ±1, the hit lands **0..timingMs late, never early**. Late-only (commit `1d64579`): a hit moved before its grid point "can land before a render's start, or before the offline scheduler's window, and is dropped", so renders and measure disagreed with live playback. Earlier (`e2deb29`) it used superdough's `nudge`, which only the sampler reads, so synth parts never moved; moving the hap itself means every output (check table, dump, render) honours it.
- **gain** (k = 4): `p.mul(gain(curve(velocity) + 1))`, so ±velocity as a factor.
- **length** (k = 7): scales `clip` by `1 + curve(length)` only where the part already has a clip; a sample without one plays to its end ("writing a clip onto it would cut it at its step": the earlier bug that cut every drum hit).

Values for arrival's theme (seed 41, `correlation: 'phrase'`, 4 beats, cps = 64/60/4 = 0.2667, `timingMs 12`, `velocity .1`) are in section 6.3, sampled per 16th over the 4-bar phrase.

**Finding (code, not docs):** `φ(k)` is rounded to 3 decimals and the `k · 40503` term moves it by ~0.00006 rad per k, so **all nine phases are identical** (2.133 rad for seed 41; likewise for any seed). Consequences: the slow wave, the beat lean and the residual share one phase, and the timing, gain and length curves have exactly the same shape, so a late hit is always a proportionally louder and longer one. The correlation the design describes (neighbours lean together, the same way every play) holds; the independence between the three curves the comment implies does not. Do not write "three independent curves". A one-character fix (a larger multiplier on k) would change the numbers in 6.3 but not the design story.

Versus `organicness` (the axis it replaces): `rand.range(-1,1) · max(0, v − .5) · 0.08` cycles of `nudge` (±0..40 ms at cps .5) and `· 0.4` of gain per hit, fresh dice per hit, sampler-only timing.

### `compressor` per part

`{ threshold (dBFS, required), ratio 4, knee 10, attack .003, release .05 }` → five control calls (`compressor`, `compressorRatio`, `compressorKnee`, `compressorAttack`, `compressorRelease`) with the Web Audio AudioParam ranges as bounds (threshold −100..0, ratio 1..20, knee 0..40, attack/release 0..1). Superdough builds a `DynamicsCompressorNode` **per hit** (`superdough.mjs:829 getCompressor` inside the per-hap chain), so the check lint warns when a part with a compressor has more than 16 onsets a bar (`COMPRESSOR_HITS`). Convention: `{ threshold: -18, ratio: 3 }` only on a sparse part whose `crest` is over ~9 (arrival's tubular bells: two strikes a bar, crest 9.4). "A master limiter is not built."

### `level` and levels by hierarchy

`level` is a plain gain multiplier applied after every axis (1 = as built; lint warns outside 0..2). The skill's hierarchy (design targets, "defaults, not rules"): name each part **foreground** (6..12 dB under the mix), **support** (10..18), **background** (16..26) or **foundation** (kick and bass, centre by convention). Over 30 dB under is inaudible: cut or raise, never leave. The lint's hard numbers: inaudible < −30 dB, dominant > −2 dB (non-foundation, when there is more than one part). Depth is meant to come from the `closer`/`farther` words (`lib/descriptors.json`: brightness ±.12, space ∓.18, weight ±.08; `background` −.15/+.20/−.12), "not level alone".

### `voices`

`scripts/check.mjs`: per hap, `load = (1 + worklets on the hap) × (duration in cycles + release · cps)`, summed over the section and divided by its bars: the average number of hits sounding at once, each "a chain of ~8 audio nodes", each `coarse`/`crush`/`shape`/`distort` worklet counting one more. Counted over the whole pattern in the section's window, so a `stack()` of textures around the song is included (`n outside the parts`). Lint warns past **40** (`VOICES`): a trace of arrival's threshold at ~50 voices showed Chrome's audio thread at 100% of its render budget (9.7 ms per 9.8 ms callback, worst 27 ms, ~400 nodes a quantum) and crackled; machine's chorus3 at ~46 (half distortion worklets) at 60–70% with the slowest callbacks over deadline. "One machine's number." Today: arrival threshold **37** (pre-mix file at `4b97ac9`: 42; `33e5066` recorded 49 before the two widest pads went from jux to sweep), contact 31, machine chorus3 28 (pre-mix 43).

### The schedule-ahead 0.3 s change (`9bcc1f7`, `web/boot.mjs`)

Querying a 13-part section costs the page's main thread 200–400 ms bursts (Fraction math in Strudel's pattern engine); Strudel drops every hit due inside a stall longer than its scheduling latency (0.1 s). `r.scheduler.latency = 0.3` after init: "what was heard as clipping was those dropped hits under load" (the offline render was unchanged: peak .951, nothing clipped). Cost: an edit, a knob or a section jump reaches the ears 0.3 s later.

### Orbits-per-reverb fix for dropouts (`4d95feb`, `bca3ee7`)

The morning's design gave every part its own orbit, so a convolver per part; dense sections dropped out. `orbitKey` (above) collapsed threshold from 13 to 5 convolvers, and a song `room` with `size` to 1. The lint's "hits a bar" density rule, which "stood in for a cause that was still unknown", was then deleted.

### What each column means (`lib/analyze.mjs`, `scripts/measure.mjs`, `web/compose.mjs levelRows`)

- **dB**: mix row = `20·log10(rms)` dBFS of the mono-summed mix; part rows = `20·log10(part.rms / mix.rms)`, the part *alone* under the mix. Unweighted RMS, not LUFS. A `*` marks a ducked part (measured alone, so un-ducked: it sits lower in the mix than its row says).
- **depth** (`depthOf`): `0.4·clamp(−relativeDb/30) + 0.3·(1 − clamp(highRatio/0.3)) + 0.3·clamp(tail/0.5)`, 0 close .. 1 far, "the three things the ear reads distance from": level, high-band share, reverb tail. The code comment marks the weights and scales as heuristics ("retune from renders"). The skill insists it is read with its three inputs: a high depth from level alone is a quiet part, not a distant one.
- **highRatio**: share of spectral energy above 4 kHz over active frames; **lowRatio**: below 150 Hz; **centroid**: energy-weighted mean frequency (Hz), the brightness metric; **tail**: energy in the last 10% of each cycle over first+last 10% (the `space` proxy); **crest**: peak/rms (the `articulation` proxy; the compressor trigger above ~9); **pan**: energy-weighted position of 10 ms windows, 0 left .. 1 right; **panStd**: its spread (movement; the skill allows one part over .2); **peak**: mono peak; **clip%**: share of samples at |x| ≥ .999 per channel (what "peak 1" hides, since a wav clamps at 1). Active frames for the spectral metrics are those within 40 dB of the stem's peak (`ACTIVE_FRAME_DB`), 2048-sample Hann frames, hop 1024.
- **masking pairs** (`masking(a, b)`): bands `low` 0–300 Hz ("where bass and kick live"), `mid` 300–3000 ("where everything else collides"), `high` 3000+. Each stem's per-frame band energy is scaled by that stem's own peak over all bands and frames, so the score is **level-independent by construction** ("this is about where a part's energy sits, not how loud it is"). A frame counts as sounding when scaled energy > 1e-4 (−40 dB of the stem's own peak). Per band: `(Σ min(x,y) / Σ max(x,y) over frames where both sound) × (frames both sound / frames either sounds)`: shared energy times time together, 0..1. Pairs are sorted by their max band.

### The mix lint rules (`scripts/lint.mjs lintMeasure`, thresholds in `MIX`)

| rule | fires when | message says |
|---|---|---|
| no headroom | mix `peak ≥ .98` or `clipped > 0`, **and** `clipped ≥ 1e-4` (0.01% of samples) | "no headroom: the mix peaks at P (D dBFS), C% of samples clip; bring levels down" |
| transients | same trigger but `clipped < 1e-4` | "transients touch full scale: a compressor on the part with the crest, not level; a master limiter is not built" |
| silent | a part's dB is not finite | "X is silent: cut it or give it something to play" |
| inaudible | part dB < **−30** | "X is inaudible (D dB under the mix): raise its level or cut it" |
| dominant | part dB > **−2**, more than one part, part not drums/bass | "X dominates: it is most of what is heard" |
| flat stage | ≥ 3 heard non-foundation parts with |pan − .5| < **.05** and width < **.2** | "flat stage: … all sit centre; give some a position" |
| masking low | pair `low ≥ .5` | "share the low band: move one up (register), thin it (density), or duck it" |
| masking mid | pair `mid ≥ .6` | "share the mids: rest where the other plays (density), an octave apart (register), darken one (brightness), or a position each" |
| no depth contrast | ≥ 3 heard parts and max−min depth < **.15** | names the shared component: level (dB spread < 4), brightness (highRatio spread < .03), tail (spread < .1), or "no one component apart" |

"heard" = finite dB and ≥ −30. The `high` band has no rule. The code comment: "the thresholds below are heuristics from the first measured songs; retune them from renders, not by argument."

## 4. The psychoacoustics rationale, tied to the code

Legend: **[science]** established perception literature, safe to state with the standard name; **[lore]** standard mixing-engineer practice, widely taught but not a perceptual law; **[design]** this repo's own choice, to be attributed to the author.

- **Masking** [science]: a louder sound raises the threshold at which a weaker one at nearby frequencies is heard (simultaneous masking; the critical-band model, Fletcher/Zwicker). The repo's `masking()` is a **proxy** for it [design]: three fixed bands (0–300, 300–3000, 3000+ Hz), shared energy × co-occurrence, deliberately level-independent so it says "these two occupy the same place at the same time", not "one hides the other". Real masking is asymmetric (low masks high more than the reverse: the upward spread of masking), level-dependent, and works on ~24 critical bands. The post should call it "where two parts overlap", not "masking as measured".
- **Precedence (Haas) effect and pre-delay** [science]: when the same sound reaches the ear from two directions within roughly 1–35 ms (up to ~40 ms for speech/complex sounds), it is localized at the first arrival and the second fuses into it. Mixing lore [lore]: a reverb pre-delay of 10–40 ms keeps the direct sound's attack and position intact in front of the reverb, so a part can be wet without going blurry. In the repo: the 8/15/30 ms silent heads of the three impulses, and `songs/rooms.strudel`'s `hall` vs `tight` A/B (same room, pre-delay removed via `irbegin`) which the author describes as "hear what the pre-delay alone was doing". `fade` (superdough's `roomfade`) is *not* a pre-delay and the code comment says so.
- **Equal loudness** [science]: at equal SPL, sounds around 2–5 kHz are heard louder than low or very high ones (Fletcher-Munson / ISO 226). **Not modelled**: the dB column is unweighted RMS, so the timpani pulse at −20.9 dB (centroid 130 Hz) is perceptually further down than a chime would be at the same number, and the author's "level 2 to be *felt* at 21" is that intuition applied by ear. State this as a limit.
- **Spectral centroid as brightness** [science]: the energy-weighted mean frequency correlates well with perceived brightness (Grey 1977 and the timbre-space literature). It is the `brightness` axis's verification metric and what the `closer`/`farther` words move (brightness ±.12 = a lowpass shift: pad lpf 200/1200/6000 Hz log, melody 300/2000/8000). Air absorption and the fact that distant sources are duller is the physical basis [science] for "darker = farther" in `depthOf`.
- **Crest factor** [science/engineering]: peak/RMS; transient sounds have a high one. The repo uses it to decide who gets a compressor (crest > ~9, sparse parts only), which is the standard reason for compressing a spiky source [lore]. The "transients touch full scale" lint versus "no headroom" is a crest-vs-level distinction.
- **Hierarchy of attention** [lore, with a design flavour]: mixing lore says the listener follows one or two things at a time; the dB bands (foreground 6–12, support 10–18, background 16–26 dB under the mix) are the author's defaults [design], not a measured law. The −30 dB "inaudible" line and −2 dB "dominant" line are lint heuristics [design]. Do not present the bands as psychoacoustics.
- **Correlated vs random humanization** [science, with care]: human timing deviations are not white noise; they are serially correlated and structured by metrical position (Repp's work on expressive timing; Hennig et al. 2011 on long-range correlations in human rhythm; the "swing"/microtiming literature). Independent per-hit jitter (dice per hit) reads as sloppiness or as a machine imitating one, because neighbouring notes do not lean together and nothing repeats the same way twice. The repo's `humanize` [design] encodes exactly that intuition: a slow wave over the phrase, a fixed lean per beat position, a small residual, seeded so the lean is the same every play. Two honesty points: (1) the three curves share one phase (section 1), so timing/gain/length are perfectly correlated with each other; (2) it is late-only, for a scheduler reason, not a perceptual one.
- **One shared room reads as one space** [science + lore]: auditory scene analysis (Bregman) groups sources by common fate and common environment; a shared reverberant signature is one of the cues that says "these are in the same place", and mixing lore says one main reverb glues a mix while a different reverb per part reads as a collage. In the repo: `room` on the song puts the same impulse on every part and `space` becomes only the send, and the orbit rule makes that literally one convolver. The earlier bug (four reverb sizes on one orbit made superdough rebuild the impulse under sounding notes, heard as pops and a "whistle") is a nice concrete cost of *not* sharing.
- **Low end stays centred and narrow** [lore, with a physical basis]: localization below ~100 Hz is poor (interaural level differences vanish for long wavelengths; ITD cues weaken), stereo bass wastes headroom and breaks mono/club playback. The repo: `FOUNDATION = drums, bass` are exempt from the flat-stage rule, the skill says kick, bass and the hook stay within ±.1, and measured bass width is .07 with pan .46 in both versions.
- **Sidechain ducking makes room for the kick** [lore]: dipping a sustained low part at every kick lets the transient through without a static level cut; the recovery time sets whether it "pumps". The repo's `duck` is superdough's per-orbit gain ramp (instant dip, exponential recovery over `duckAttack`), and the fallback square-wave dip on a driven pad is a written admission that the real thing needs a source.
- **Panning vs width** [lore]: a position is where a source sits; width is how much of the field it occupies. The repo separates them mechanically: `position` is a constant pan offset, `width` is a slow LFO sweep (or `jux` doubling), and the sweep's centre moves with the position. Perceptually [science], the "width" of a stereo source is read from interchannel decorrelation; a slow pan sweep is movement, not decorrelation, and `jux(rev)` (a reversed copy on the other side) is closer to real width, which is also why it costs double the voices.

## 5. Strongest story, surprises, caveats, phrasing to avoid

**Strongest story for a reader:** the arrival threshold section with 13 parts, one measure table, and the five-line lint: the loudest thing in the climax was the *impact hit* (5 dB under the mix), the choir out-sang the piano theme, the timpani and the glockenspiel doubling were literally inaudible (−30, −40 dB), every part sat centre in one of five reverbs. Then a scene: one hall, a position each, levels by role, the doubling swapped for an instrument that can be placed; lint clean, peak halved, the theme in front. The point is not "it sounds better" (the repo's own rule: "verified directionally is the strongest claim") but that a mix became a *described* object with numbers, and the description is what an agent can act on.

**Surprising findings:**
1. The glockenspiel doubling came up 27 dB by *lowering* its level (.45 → .2) and changing the instrument: level is per-sample, the sample was the problem.
2. Masking is level-independent by construction, so the 10 dB choir cut did nothing to its masking score; brightness did (.72 → .45).
3. Position is real in the events but the measured pan of a wet part sits near centre anyway (pad4: events at pan .33, measured .49) because the hall's stereo return dominates; the piano sample is right-heavy by itself (.74 with no position).
4. All nine humanize phases collapse to one (rounding); the design's three independent curves are one curve at three scales.
5. The dropouts that felt like clipping were dropped hits (scheduler latency) and convolver count, not levels: the offline render never clipped.
6. Machine's kit still peaks at 1.0 alone at level .3, because distortion comes after gain.

**Caveats and limits (what is not modelled):**
- No per-part EQ beyond a single tilt: `brightness` is one lowpass per layer (drums: lowpass below .5, highpass above), `weight` is gain/low voicing, `sweep` is a closing lowpass. No parametric EQ, no high-pass on pads, no dynamic EQ.
- No true pre-delay control: only the silent head baked into an impulse (and `irbegin` to shorten it); `fade` is a head ramp. The synthetic reverb has no pre-delay at all.
- No pitch-preserving stretch: `transpose` on a sample part changes speed.
- Masking is a proxy (three bands, level-independent, symmetric). Depth is a heuristic with hand-picked weights. dB is unweighted RMS, not loudness. `pan` reads the rendered energy, room included.
- No master bus: no limiter, no bus compressor; the "no headroom" lint on machine cannot be cleared by level.
- Humanize: late-only, shared phase, no `duckonset`, no swing interaction documented.
- Measure renders four bars by default (`--cycles` for more); a 12-bar section's later bars are not measured.
- The shoebox IRs are geometry plus noise, "not a real room's diffusion".
- Voices threshold (40) and mix lint thresholds are one machine's numbers and "heuristics from the first measured songs".

**Phrasing to avoid (routine repo changes would falsify it):**
- Exact lint thresholds, dB targets, `depthOf` weights, the 40-voice line, the three IR parameter sets, the 0.3 s latency: quote them as "at the time of writing" or link the file, they are all marked `ponytail: retune`.

- "Arrival's threshold runs five convolvers" (that was the intermediate state; today it is one; before that 13).
- "The choir was 9 dB down" etc. from the header: quote the measured table with a date.
- Anything implying `-mixed` twins still exist (promoted, deleted in `3517d4d`).
- "It sounds better" / "fixed the masking": the bowed-vibraphone pairs are .58/.59 against a .6 rule.
- "Glockenspiel" as a threshold part: it is a vibraphone now.
