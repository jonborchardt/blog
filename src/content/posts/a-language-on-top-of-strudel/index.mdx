[Strudel](https://strudel.cc), and the density of that snippet is the whole reason it is worth

This series is about [strudel-bench](https://jonborchardt.github.io/strudel-bench/), a small system
that sits on top of Strudel so that a long, through-composed piece can be written, read and edited

<Callout variant="info" title="Strudel in sixty seconds">

Strudel is a JavaScript port of TidalCycles, the Haskell live-coding environment. It runs in a
browser, it makes sound through Web Audio, and you can edit it while it is playing. A genuine port
rather than an homage: it uses the same mini-notation grammar Tidal does.

Three ideas carry the whole thing.

**A pattern is a pure function from a span of time to a list of events.** Nothing is stored. You ask
a pattern what happens between cycle 0 and cycle 4, and it computes the answer. This is why the whole
system can be tested headlessly with no audio hardware: a checker just queries.

**Mini-notation is a string DSL for rhythm**, parsed inside double-quoted strings.
<a href="https://strudel.cc/#cygiYmQgc2QiKQ%3D%3D" target="_blank" rel="noopener"><code>s("bd sd")</code></a>
is two events splitting one cycle.
<a href="https://strudel.cc/#cygiYmQgfiBzZCB%2BIikuYmFuaygiUm9sYW5kVFI4MDgiKQ%3D%3D" target="_blank" rel="noopener"><code>~</code></a>
is a rest,
<a href="https://strudel.cc/#cygiYmQgW3NkIHNkXSIpLmJhbmsoIlJvbGFuZFRSODA4Iik%3D" target="_blank" rel="noopener"><code>[a b]</code></a>
subdivides a slot,
<a href="https://strudel.cc/#cygiYmQgPHNkIGNwPiIpLmJhbmsoIlJvbGFuZFRSODA4Iik%3D" target="_blank" rel="noopener"><code>{"<a b>"}</code></a>
alternates one per cycle,
<a href="https://strudel.cc/#cygiYmQgaGgqMiIpLmJhbmsoIlJvbGFuZFRSODA4Iik%3D" target="_blank" rel="noopener"><code>a*2</code></a>
doubles the speed,
<a href="https://strudel.cc/#cygiYmRAMyBzZCIpLmJhbmsoIlJvbGFuZFRSODA4Iik%3D" target="_blank" rel="noopener"><code>a@2</code></a>
makes a slot twice as wide, and
<a href="https://strudel.cc/#cygiYmQoMyw4KSIpLmJhbmsoIlJvbGFuZFRSODA4Iik%3D" target="_blank" rel="noopener"><code>bd(3,8)</code></a>
distributes three hits across eight positions as evenly as possible.

**The unit of time is the cycle.** A cycle is not intrinsically a bar. That is a convention you
adopt, and Strudel's own docs show it as
<a href="https://strudel.cc/#c2V0Y3BtKDE0MC80KQpzKCJiZCo0LCBbfiBzZF0qMiwgaGgqOCIpLmJhbmsoIlJvbGFuZFRSODA4Iik%3D" target="_blank" rel="noopener"><code>setcpm(140/4)</code></a>,
which is 140 BPM in 4/4 once you divide out the beats. `cps` is cycles
per second, and the default is 0.5, so one cycle every two seconds.

**One cycle, one bar.** strudel-bench adopts that convention and makes it structural. A meter of 4/4
means sixteen sixteenth steps in one cycle, and `bpm: 64` becomes `cps` of 64/60/4. So when a song
says it is 59 bars, it is 59 cycles.

Everything past that is combinators, and they are the good part.
<a href="https://strudel.cc/#bigiMCAyIDQgPDYgNz4iKS5zY2FsZSgiQzptaW5vciIpLnMoInNhd3Rvb3RoIikubHBmKDE1MDApLmRlY2F5KC4yKS5zdXN0YWluKDApLmp1eChyZXYp" target="_blank" rel="noopener"><code>.jux(rev)</code></a>
plays a reversed copy in the other ear.
<a href="https://strudel.cc/#cygiaGgqOCIpLmJhbmsoIlJvbGFuZFRSODA4Iikuc29tZXRpbWVzQnkoMC40LCB4ID0%2BIHgucGx5KDIpKQ%3D%3D" target="_blank" rel="noopener"><code>{".sometimesBy(0.4, x => x.ply(2))"}</code></a>
doubles up some events. Continuous signals are patterns too, so any control can be modulated:
<a href="https://strudel.cc/#bm90ZSgiYzIgZWIyIGcyIGJiMiIpLnMoInNhd3Rvb3RoIikubHBmKHNhdy5yYW5nZSgzMDAsIDgwMDApLnNsb3coOCkp" target="_blank" rel="noopener"><code>.lpf(saw.range(300, 8000).slow(8))</code></a>
sweeps a filter over eight cycles.

Strudel also already has arrangement.
<a href="https://strudel.cc/#YXJyYW5nZSgKICBbNCwgcygiYmQqNCIpLmJhbmsoIlJvbGFuZFRSODA4IildLAogIFsyLCBzKCJiZCo0LCBoaCo4IikuYmFuaygiUm9sYW5kVFI4MDgiKV0KKQ%3D%3D" target="_blank" rel="noopener"><code>arrange([4, patA], [2, patB])</code></a>
does what you would hope. It is
important to say that plainly, because the usual version of this story ("the library couldn't
sequence, so I built a sequencer") would be false here.

To go further, the <a href="https://strudel.cc/workshop/getting-started/" target="_blank" rel="noopener">Strudel workshop</a> starts
from zero and plays every example in the page.

## Where it stops helping

The problem is not sequencing. It is per-part state, and it has four faces.

**There is no baseline.** Strudel has no concept of what a part normally sounds like. Every part in
every section is written from scratch. Nothing in the language can say "the same pad, a shade
darker."

**Later calls silently replace earlier ones.** `.lpf(2000).lpf(800)` is 800. The first call is gone,
with no warning. So you cannot layer two independent adjustments onto one part without knowing
exactly what else already wrote that control. Hold on to this one; it comes back.

**Nothing is named.** A live-coding session is one expression. A long piece is dozens of them, and
they are positional.

**One musical idea is N edits.** "The bowed strings should be a shade darker everywhere" is one
number if parts have baselines. Written out, in a 59-bar piece where the same bowed strings appear
in every section, it is eight separate filter cutoff values, each already different because each was
adjusted for its own section.

None of this makes Strudel badly designed. It is built for a four-bar loop you are editing live in
front of an audience, and it is excellent at that. A 59-bar through-composed score is off-label use.

## What strudel-bench is

A static web page and a handful of Node scripts, with no bundler and no build step beyond copying
files. The page has two views that ship and one that stays local:

- **Compose** is where a song is written and played: the editable source, the plain Strudel it
  expands to (regenerated as you type), and a Mix card where every slider, menu, chord button and
  word is a source edit. [The editor post](/knobs-in-the-code/) walks through it.
- **Examples** is a scrollable showcase of playable cards, one per axis, word, modifier, harmony
  form, material and section edit, each with before-and-after variants you can play and an editable
  pane.
- **Samples** is a local-only workshop for your own sample packs and named regions of a file.

The same page deploys to GitHub Pages on every push. There it has no server, so saving goes to the
browser's local storage, the sample packs stream from Strudel's CDN, and exporting an MP3 renders
and encodes in the browser. Locally, the page watches the song files and re-evaluates in place when
one changes on disk, so an edit lands without stopping playback.

The scripts are the other half of the product, and the rest of this post is mostly about two of
them: `check`, which prints everything a song is without playing it, and `dump`, which prints the
Strudel a song compiles to.

## Sections and parts

The layer strudel-bench adds comes down to one idea: a piece is a list of named sections, each
holding parts, each part described by where it sits on a fixed set of perceptual axes.

```js
song({ bpm: 64, key: 'D:minor', seed: 41, kit: 'RolandTR808', packs: ['rooms'],
       room: { ir: 'hall', size: 3.2, damping: 4500 } }, [
  section('contact', 8, { role: 'climax', progression: 'i VI III VII',
    drums:   { ...pulse, density: .5, weight: .8 },
    bass:    { ...pedal, density: .75, notes: '0 0 4 0', weight: 1 },
    melody:  { ...theme, density: .55, brightness: .65, width: .6, level: 1.1 },
    melody2: { ...signal, density: .5, level: .7 },
    pad:     { ...strings, density: .8, brightness: .5, weight: .7, width: .75 },
  }),
])
```

That is five of the eleven parts in the first climax of a piece called `arrival`, the one the last
post in this series is about. `pulse`, `theme`, `signal` and `strings` are ordinary JavaScript
objects declared once at the top of the file and spread into every section that uses them, which is
where the baseline lives: `theme` is the piano, and this section asks for it a little denser and
brighter than usual.

Each part is an instance of one of eight kinds. Four are the rhythm section and the bed: **drums** (a
kit on a step grid), **bass**, **melody** and **pad** (the chord, voiced). One is transition
material: **fx**, a riser into the next section or an impact on the downbeat. Three arrived later and
are about bringing your own sound in: **sample** (a trimmed region of any file, sliced and
re-sequenced), **perc** (one bare sound on a written rhythm) and **raw** (a plain Strudel pattern,
placed inside a section so the tooling can see it). A section is not eight slots. It can hold as many
parts of a kind as it wants, numbered: the biggest section of `arrival` runs a melody through
`melody6` and a pad through `pad4`, and the whole piece is 62 parts across 8 sections.

Every axis value is a number from 0 to 1, and **0.5 means the part's baseline**. That is the load
bearing convention, and a later section is about why it is more than a convention.

Not everything in those objects is an axis. `sound`, `notes` and `level` are *material*: literal
values rather than positions on a scale. That is why `level: 1.1` above is legal and an axis at 1.1
would not be. Level is a plain gain multiplier applied after every axis has had its turn, which is
also why the axes have no volume of their own. Material has grown into a long list, and most of it
belongs to later posts: written rhythm grammars, patches, harmony, and the mixing keys (`position`,
`room`, `duck`, `humanize`) that [the mixing post](/mixing-as-a-scene/) is entirely about.

The twelve are density, drive, brightness, weight, space, articulation, aggression, groove,
variation, organicness, width and register. They split two ways that matter.

By **how you verify them**: four are direct (brightness really is the spectral centroid in hertz,
and you can measure it), six are proxies (space is measured as how long energy persists after an
onset, which is a stand-in for reverb, not reverb itself), and two can only be checked by reading the
event stream. Drive moves which sixteenth a hit lands on without changing how many there are, so no
audio metric moves at all.

By **what they can accept**: structural axes take a number and nothing else, because they decide the
grid before any pattern exists and there is nothing for a signal to be sampled at. Continuous axes
take a number, a Strudel signal, a `ramp(a, b)` across the section, or one of the named movements
(`wobble`, `drift`, `pulse`, `swell`) that already know how long the section is.

The interesting part of that grid is the empty cells. Drums have no register, because a kit has no
pitch. Bass has no width, because widening the low end is a mix mistake. A sustained pad has no
groove, because there is no offbeat to swing. A riser, a sliced sample and a raw pattern implement
only the four cells that make sense for a sound whose rhythm is already decided.

And here is the rule that makes the holes trustworthy rather than embarrassing: an unimplemented axis
is **accepted and does nothing, visibly**. Set `register: .9` on drums and it is not an error. The
value goes into the file, the checker prints it back, and the audio is byte-identical to leaving it
out. The alternative, pitching the samples up to honour the request, would be a guess wearing the
costume of a feature.

## Why 0.5 is nothing

It would be easy to make 0.5 mean "apply the baseline value," which sounds the same and is not.
Here is the primitive:

```js
if (typeof value === 'number') {
  if (value === 0.5 || (noopBelow && value <= 0.5)) return pat;
  return pat[name](fn(value));
}
```

At exactly 0.5 it returns **the same object**. Not an equivalent pattern, not the baseline re-applied.
The same one. So there is no rounding and no "close enough": an axis sitting at its baseline cannot
possibly have done anything.

That matters because it makes the declarative file a *description* rather than a *transformation*.
Writing out the values a part already has changes nothing, so edits do not accumulate error, and any
axis you leave out is exactly the same as writing it at 0.5.

It is also enforced by test, for the four core layers plus fx and sample: each layer is built twice,
once with no axes and once with one axis at 0.5, and the two event streams must be byte-identical.
The complement asserts that every one of those cells *does* move something at 0 or at 1, so a cell
that quietly does nothing anywhere fails the suite. The two newest layers, perc and raw, mostly
borrow their cells from drums and sample by object identity rather than carrying tests of their own,
which is the honest footnote to "enforced".

## Order matters, and here is the bug that proves it

Remember that a second `.lpf()` replaces the first. Now put two axes on the same part that both want
to touch the filter cutoff. Brightness sets it. Weight scales it. If weight runs second and *sets*
rather than *scales*, brightness is silently erased.

That is not hypothetical. It shipped, and the commit that fixed it says so:

> bass.weight set an absolute lpf and ran after bass.brightness in the spectral phase, so brightness
> was discarded whenever weight was set

The tell is in the numbers: with the bug, `{brightness .9, weight .9}` and `{brightness .5, weight
.9}` both produced a cutoff of 317.77 Hz. A knob doing nothing, silently, and only in combination
with another knob.

Both axes live in the same stage, so this is an ordering question *inside* one stage rather than
between two. The figure below shows the fixed version run in each direction, which kills the other
knob: with the order reversed, weight is the one that contributes nothing.

The fix was to give the system a way to say "multiply this control rather than set it," and then to
fix the order so that the cell which sets always runs before the cell which scales. The rule that
came out of it is one line in the README:

> Adapters run in fixed phases, because transformations do not commute.

Seven phases, in this order: structural, timing, pitch, articulation, spectral, spatial, level.
Structural runs first because it builds the material everything else transforms, over a plain object,
before any pattern exists. Level runs last so nothing can undo the balance after it.

A cell declares which phases it participates in, and declaring a phase that does not exist is an
error rather than a silent no-op.

## The layer can be decompiled

`song()` and `section()` are ordinary functions that *call* Strudel to build patterns at runtime.
There is no template, no intermediate representation, no generated file. So "what Strudel does this
actually become?" has no answer you can read.

Unless you instrument the call. For the duration of one evaluation, the dump replaces every Strudel
core function and every method on the pattern prototype with a wrapper that records what it was
called with, builds a map from each pattern object to the call chain that produced it, prints the
chains, and then restores every original.

The arithmetic operators are non-configurable getters, so the wrapper never sees
which one it is. It recovers them by **probing the closure with 7 and 3 and looking the answer up in
a table**. If it comes back 10 it was addition, 21 multiplication, 4 subtraction.

Four lines of declarative source become thirty-five lines of plain Strudel, and it plays. Here is
the same four bars, rendered from each:

They are the same music, and that is checkable rather than a matter of taste: the two files produce
identical event streams, 36 events each, matching on every onset, duration, sound and note. The
expanded form is not quite bit-identical audio, because the dump prints numbers to six significant
figures, which moves a filter cutoff by a few parts in ten million.

Two honest limits. The expansion is the literal call sequence, not a minimised one, so you see
`.lpf(2000)` followed by `.lpf(3031.43)`: the baseline, then the axis overriding it. No human would
write that. And it expands hand-written code too, so your own names are inlined away.

Why it matters: the abstraction is falsifiable. You can ask what `brightness: .65` did and get a
number, you can check that nothing is happening behind your back, and you can paste the result into
strudel.cc and walk away. The page's export button ships exactly this, with the sample-pack preamble
strudel.cc needs prepended. It is a layer on top of Strudel, not a replacement for it.

## The layer does not forbid raw Strudel

The 59-bar piece is not purely declarative. Alongside the sections there are eleven hand-written
plain-Strudel textures, gong swells and a wind bed and a low drone, stacked in with Strudel's own
`arrange`.

The declarative half models what it can model. Everything else stays raw, side by side, in the same
file. The mixer's solo button, the dump and the section loop see only the parts, and that turns out
to be a useful diagnostic rather than a limitation: a sound that survives soloing is in the layers,
and one that vanishes is in the textures. The checker's load count is the one tool that sees both,
and it says so on every section header: `~37 voices at once (3 outside the parts)`.

For a texture that belongs to one section rather than the whole piece there is now a middle path, the
`raw` part, which puts a plain pattern inside the section so that mute, solo, check and dump all see
it.

## Reading a song without playing it

One command tells you what you have. This is the checker on the small demo song that ships with the
page, trimmed to two of its three sections:

```text
  sounds
    RolandTR909_bd:0         Bassdrum-01.wav (4 variants)
    RolandTR909_sd:0         naredrum.wav (16 variants)
    piano:0                  pitched, 29 samples A0..C8
  [0-4) intro (establish)  ~6 voices at once
    harmony C:minor  i VI -> Cm Ab
    drums       6/cyc  density=0.3 space=0.6             sparse
    pad         3/cyc  space=0.8 articulation=0.2 brightness=0.35   dreamy, dark
  [4-12) verse (develop)  ~6 voices at once
    harmony C:minor  i VI -> Cm Ab
    drums      15/cyc  density=0.6 groove=0.6
    bass        4/cyc  weight=0.7 register=0.3            massive
    melody    5.5/cyc  density=0.5 brightness=signal sound=piano follow=true phrase=2 notes=0 2 3@2 ~ 4 3 2 0 2 3@2 ~ 5@2 4
    pad         3/cyc  space=0.6
    fx          2/cyc  riser=2
  arc: intro 9 | verse 29.5 | drop 59
```

Every section, every part, onsets per cycle, every axis value, the chords each section actually
resolved to, the file behind every sound name, and a load figure per section. The words at the end of
a part's line are the vocabulary run backwards: `dreamy, dark` is what the values say, in the same
vocabulary [the next post](/say-darker/) uses to change them. It runs in Node, with no audio,
in a second or two for a song this size and about a quarter of a minute for the 59-bar one.

It also refuses things. A typo in an axis name is not a silent no-op, it is a build error that names
both lists it would have accepted:

```text
unknown key "brightnes" on drums in section "a" (axes: density, drive, brightness, weight,
space, articulation, aggression, groove, variation, organicness, width, register;
material: template, sounds, fill, level, position, duck, ...)
```

A sound name the loaded packs do not have fails the same way. That single behaviour is what makes a
declarative layer safe to work in quickly, and it is why the checker rather than the test suite is
the inner loop.

A second script, `lint`, applies musical rules to the same table: a climax exists and is the most
energetic section, no two consecutive sections are identical, no section stacks two raw sawtooths,
every melody and bass writes its own notes rather than playing a seeded default, every axis is in
range, and no section asks for more voices at once than a laptop's audio thread can render. Warnings
for taste, errors for the impossible.

And then there is the line that summarises a piece better than any paragraph I could write:

```text
arc: void 1.1 | signal 4.1 | approach 21.6 | contact 57.6 | will 14.4 | plea 37 | threshold 67.3 | after 7.4
```

And here is the one idea in that piece that the language expresses in a single word. Two melodies
over the same four chords: the piano is told to `follow: true`, so its line is re-rooted on each
chord as the harmony moves, and the handchimes are told `follow: false`, so they play the same three
notes bar after bar, indifferent to the chords going past.
